// Supongamos que 'miner' es tu instancia global del minero
let isRunning = true;

function toggleMiner() {
    const btn = document.getElementById('miner-control');
    const statusText = document.getElementById('miner-status');

    if (isRunning) {
        // Detiene la actividad del minero
        miner.stop(); 
        
        // Actualiza la interfaz
        btn.innerText = "Reanudar Minero";
        btn.style.backgroundColor = "#4CAF50"; // Verde para reanudar
        statusText.innerText = "Detenido";
        isRunning = false;
        
        console.log("Minería pausada por el usuario.");
    } else {
        // Inicia o reanuda la actividad
        miner.start();
        
        // Actualiza la interfaz
        btn.innerText = "Detener Minero";
        btn.style.backgroundColor = "#f44336"; // Rojo para detener
        statusText.innerText = "Ejecutando";
        isRunning = true;
        
        console.log("Minería reanudada.");
    }
}

Ajuste de Intensidad: En lugar de solo "encendido/apagado", podrías añadir un control para el throttle (aceleración). Esto permite al usuario decidir si quiere que el minero use el 10% o el 80% de su procesador.

import streamlit as st
import redis
import os
import pandas as pd

# Configuración de Redis
REDIS_HOST = os.getenv("REDIS_HOST", "redis") 
r = redis.Redis(host=REDIS_HOST, port=6379, decode_responses=True)

st.set_page_config(page_title="GitHub Miner", layout="wide")
st.title("📊 GitHub Word Miner - Real Time")

# --- SECCIÓN DE CONTROL EN EL SIDEBAR ---
st.sidebar.header("Configuración y Control")

# 1. Verificar el estado actual en Redis (por defecto 'running' si no existe)
current_status = r.get("miner_status") or "running"

# 2. Botón dinámico para detener/reanudar
if current_status == "running":
    if st.sidebar.button("🛑 Detener Actividad del Miner", use_container_width=True):
        r.set("miner_status", "stopped")
        st.rerun()
else:
    if st.sidebar.button("▶️ Reanudar Actividad del Miner", use_container_width=True, type="primary"):
        r.set("miner_status", "running")
        st.rerun()

# Mostrar estado visualmente
status_color = "green" if current_status == "running" else "red"
st.sidebar.markdown(f"Estado del Miner: :{status_color}[{current_status.upper()}]")

# ---------------------------------------

top_n = st.sidebar.slider("Ver Top N palabras", 5, 50, 10)
refresh_rate = st.sidebar.selectbox("Refresco (segundos)", [2, 5, 10], index=0)

data = r.zrevrange("word_ranking", 0, top_n - 1, withscores=True)

if data:
    df = pd.DataFrame(data, columns=["Palabra", "Frecuencia"])
    st.subheader(f"Top {top_n} palabras encontradas")
    st.bar_chart(df.set_index("Palabra"))
    st.table(df)
else:
    st.info("Esperando datos del Miner... Asegúrate de que el contenedor 'miner' esté corriendo.")

# Lógica de refresco automático
st.fragment(run_every=refresh_rate)(lambda: st.rerun())()

Interfaz Reactiva: El botón cambia de color y texto dependiendo de lo que lea de Redis. Si el estado es stopped, el botón aparece resaltado para reanudar.

Este es un error de seguridad muy común y, de hecho, GitHub te está haciendo un favor. El "Push Protection" detectó que en tu archivo docker-compose.yml (específicamente en la línea 11) escribiste directamente un GitHub Personal Access Token (PAT).

GitHub bloquea el push porque, si ese token llega al repositorio, cualquier persona con acceso a él podría usar tu cuenta.

Cómo solucionarlo correctamente
Para arreglarlo sin comprometer tu seguridad, debes usar Variables de Entorno.

1. Limpiar el archivo docker-compose.yml
Elimina el token real del archivo y usa una referencia. Por ejemplo:

YAML
services:
  miner:
    # ... otras configuraciones ...
    environment:
      - GITHUB_TOKEN=${GITHUB_TOKEN}  # No pongas el token aquí
2. Crear un archivo .env
En la misma carpeta donde está tu docker-compose.yml, crea un archivo llamado .env (si no existe) y pon tu token ahí:

Plaintext
GITHUB_TOKEN=ghp_tu_token_secreto_aqui
3. ¡Muy importante! Ignorar el .env
Asegúrate de que tu archivo .gitignore contenga la línea .env para que este archivo nunca se suba a GitHub.

Cómo limpiar el historial de Git
Como el secreto quedó guardado en un "commit" local, Git intentará subirlo de nuevo aunque lo borres ahora. Tienes dos opciones:

Opción A: Corregir el último commit (Si no has hecho más cambios)
Si el error está en tu último commit, haz los cambios en el archivo y luego ejecuta:

git commit --amend --no-edit

git push

GitHub te dio un enlace en el error (termina en .../unblock-secret/...). Si haces clic ahí, puedes autorizar ese secreto específico para que te deje subirlo. Solo haz esto si es un token de prueba o si realmente no te importa que sea público (aunque nunca es buena idea).
